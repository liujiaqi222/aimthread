# Focus Interval 在系统时间回拨时切分，允许重叠，投入按差值求和

计时进行中，如果服务检测到系统时间往回跳（两次 tick 之间单调钟增量比墙钟增量多出 5 秒以上），就把当前 Focus Interval 切成两段：旧区间的 `end_at` 取它的 `start_at` 加上单调钟测得的时长，新区间从跳变后的墙钟时间开始。这样每个区间内部都没有经历过跳变，`end_at − start_at` 就是真实时长，有效投入严格按 `SUM(end_at − start_at)` 计算，不另存 duration 字段。

代价是同一 Session 内的区间可能在时间轴上重叠：新区间的 `start_at` 可以早于前一个区间的 `end_at`。这是有意的，不是 bug：

- 数据库只约束单个区间 `end_at >= start_at`（允许零长度，PRD 要求小于一秒也如实保存），**不得**加 `next.start_at >= prev.end_at` 之类的相邻约束。
- 区间先后以单调递增的 `seq` 为准，不按 `start_at` 排序；"关闭最后一个区间"和按顺序展示都用 `seq`。
- 界面不要求区间在时间轴上首尾相接。

墙钟往前跳和漏报的睡眠表现相同（墙钟增量远大于单调钟增量），无法区分，所以不切分，而是进入恢复核对，由用户决定是否补入。

决定来源：[计时检查点与中断恢复算法](https://github.com/liujiaqi222/aimthread/issues/57)。

## Considered Options

- **存 `start_at` + 单调钟测得的 `duration`，不切分**：重叠照样会在后续区间出现（墙钟往回走后，用墙钟标注的时间轴必然倒退），而且 `end_at` 变成推算值，与 `duration` 两套数据需要约定以谁为准。
- **不处理，负时长按 0 计**：少算投入，违反"不产生负时长"和如实记录。
- **往回跳也进入恢复核对**：单调钟已精确测出真实时长，没有不确定性，核对是多余打扰，核对后继续计时仍会重叠。
