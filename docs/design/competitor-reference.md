# 竞品参考与 AimThread 的取舍

核对日期：2026-10-13。依据为官网、官方说明中的功能描述与展示材料；没有把这些来源当作已完成应用内操作验证。

本节的界面建议是针对 AimThread 的设计推导，不是竞品原文或功能承诺。

## Things：内容与按需展开

官方的 [Beautiful To-Dos 与 Today 展示](https://culturedcode.com/things/features/) 描述了任务打开时展开细节、次要字段按需出现的交互。

对 AimThread 的启发：当前任务应该直接承载任务说明、资源与接续提示，其他任务收在选择入口中。用户选好工作后，不必同时面对任务管理表单。

参考交互层级；新设计独立探索字体、颜色、容器和导航。

## Sunsama：从选择进入单项工作

官方 [Focus Mode 说明](https://help.sunsama.com/docs/usage-guides/focus-mode/) 将专注视图定义为围绕当前任务的简洁界面，并支持启动任务计时后进入该视图。

对 AimThread 的启发：准备与专注有不同的信息密度。准备时可以选择工作，开始后把任务切换、统计和管理入口收起，保留本次工作及计时控制。

AimThread 沿用用户确认的离开限制。跨页面计时、桌面悬浮条、日历排程不作为本轮 redesign 的新增内容。

## Session：明确工作、计时、回看

[Session 官网](https://www.stayinsession.com/) 展示了明确本次工作、开始计时、回看投入与结束后记录的产品链路。

对 AimThread 的启发：计时器应该清楚可见，并与正在做的工作放在同一视线内。任务标题、说明和资源提供工作上下文；时间提供执行反馈。

用户要求参考 Session 的工作与计时呈现，未要求复制其视觉或其他功能。结束反馈和接续提示按用户要求保留现有方式。

## Llama Life：选定任务后可以立即开始

官方 [How To](https://llamalife.co/howitworks) 说明列表顶部任务会载入计时器，用户点击播放开始。

对 AimThread 的启发：任务选择与开始计时之间应该只有一个明确动作，当前工作必须容易辨认。

AimThread 的任务已由外部 AI 拆小，产品承接现成任务。新建、排序或 AI 写入任务不应悄悄替换一个仍有效的当前选择。

## 合成原则

| 用户需要 | 采用的设计原则 | AimThread 的具体表现 |
| --- | --- | --- |
| AI 写了任务，回到产品就能执行 | 任务内容与执行入口相邻 | 当前任务、说明、资源、计时模式和开始按钮同屏 |
| 开始后聚焦工作 | 状态变化时减少选择 | 收起任务列表与统计，展示任务和计时器 |
| 每轮投入可追踪 | 工作与时间明确关联 | 每轮都有时间边界、实际投入和目标／任务归属 |
| 看见长期执行情况 | 用真实数据回看 | 日／周／月／年投入、目标分布、完成任务和记录下钻 |

竞品提供交互参考。产品架构围绕「外部 AI 计划 → Web 执行 → 真实记录 → 统计跟踪」建立，不把多个竞品的全部模块拼进首页。
