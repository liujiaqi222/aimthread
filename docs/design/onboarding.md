# 首次打开与 Onboarding redesign

日期：2026-10-13

状态：用户已要求优化首次打开体验；下述流程为待确认提案，不代表已实施。整体遵循外部 AI 规划、AimThread 执行与跟踪的产品定位。

## 1. 目标

首次打开时，让用户理解产品用途、找到进入执行的路径，并到达可以开始计时的当前工作。已有 AI 计划的用户不应重新填写一遍目标与任务。

首次成功的产品行为是用户主动开始一次真实计时。连接地址复制成功、授权完成、目标写入和开始计时是不同状态，反馈需要分别对应真实发生的行为。

## 2. 当前流程事实

当前空实例的典型路径为：登录／建立账户 → 首次配置 → 目标标题 → 可选理由所在的第二屏 → 保存目标 → 首页 → 点击开始。

核对依据：`src/app/login/page.tsx`、`src/app/setup/page.tsx`、`src/app/onboarding/page.tsx`、`src/components/onboarding/onboarding-flow.tsx`、`src/app/(app)/today/page.tsx`。

- Setup 检查数据结构后，展示独立的时区和周起始设置页。
- 目标标题是必填；理由文字可选，但手动路径仍经过第二屏才能保存。
- AI 路径是目标标题页上的次级文本入口，目前以教程、复制地址／话术和手动检查目标为主。
- 检查目标可以证明计划已写入，不能单独证明 MCP 客户端连接成功。
- 已登录、完成 Setup 且有活跃目标时，现有逻辑直接进入首页。

优化重点是路径长度、AI 入口的可见性和写入后到执行的衔接。账户与必要的安全授权仍按实际部署要求处理。

## 3. 提案：按真实状态进入

```text
首次打开
├─ 已有未结束计时 → 恢复当前工作与计时
├─ 已有可执行目标／任务 → 当前工作首页
└─ 没有可执行目标 → 简洁欢迎页
   ├─ 连接外部 AI，写入计划
   │  └─ 展示已写入目标和任务 → 选择工作 → 首页开始
   └─ 手动创建目标
      └─ 只填标题即可保存 → 首页开始
```

没有活跃目标但有历史数据的用户，不等于首次使用。应提供建立／重新启用目标与查看足迹的入口，避免重播完整介绍。

### 3.1 首屏

建议文案：

> 用 AI 做计划，在这里开始执行。
>
> 接收目标与任务，计时，并查看真实投入。

主入口建议为「连接外部 AI」，说明外部 AI 可以写入已经拆好的计划；次入口为「手动创建目标」，仅需一个标题。

可以配一个简短、明确标注为示例的界面预览，展示任务说明、开始按钮与记录的关系。预览不生成真实目标、计时或统计。

避免轮播介绍、功能打卡、偏好问卷和要求用户先写目标理由的必经屏幕。首屏用品牌与清楚的主操作即可；正式左侧导航在进入应用工作区后出现。

主次入口排序与示例预览仍待用户确认。

### 3.2 外部 AI 路径

按顺序提供完成连接所需的地址、外部授权入口和简短话术。具体客户端操作指引在实施时核对，不以历史 UI 文案代替当前客户端事实。

同时支持两种用户状态：已有计划时，请 AI 将现有计划写入；尚无计划时，在外部 AI 讨论并确认后写入。避免默认要求已有计划的用户重新规划。

用户返回应用时建议重新检查已写入数据，保留「检查已写入计划」作为手动重试入口。只有服务端真实读到目标与任务，才展示写入成功。

- 没有读到目标：说明尚未发现已写入计划，保留操作指引，不把它直接诊断成连接失败。
- 只有目标、没有任务：允许直接围绕目标开始，也可继续让 AI 写入任务。
- 有一个已选工作：直接呈现当前工作，不增加重复确认。
- 有多个目标且没有明确选择：用首页同款选择弹窗确定工作。
- 检查失败：保留当前信息与重试入口，也能转到手动路径。

产品可以明确表达已有计划和当前任务，无需再弹一遍成功向导。计时仍由用户主动点击开始。

### 3.3 手动路径

只要求目标标题，保存后进入首页。目标说明、个人理由、资源与任务都可以之后添加。可选任务输入如出现，不能成为进入执行的条件。

保存中保留输入；失败原位重试；重复提交不能创建副本。切换到 AI 路径或中断后返回时保留草稿，检测到同一已保存目标时不重新创建。

### 3.4 第一次执行

沿用正式首页的当前工作布局，不建立一套特殊的教学计时器：

- 展示实际目标、任务、AI 写入的说明与资源。
- 计时模式使用默认值或已有偏好，提供紧凑的修改入口。
- 唯一主操作是「开始专注」或对应正计时开始动作。
- 任务切换、补充说明等按需操作，不要求点击所有功能才能开始。
- 第一轮结束、记录与接续提示遵循已确认规则，不新增 onboarding 专用结束弹窗。

## 4. 基础设置与界面建议

基础设置建议尽量采用可解释的默认值：以浏览器建议时区初始化，周起始与计时参数采用默认值，之后能在设置调整。默认值必须实际保存，不能仅在前端显示。

技术就绪检查建议在后台完成，失败时展示具体恢复信息；数据库、schema 等信息在出现相关问题时提供，不作为正常首次进入的主内容。必要的账户创建与授权保留，具体是否合并页面另作实现评估。

首次引导独立使用简洁画面。进入正式工作区后采用已确认的左侧侧边栏；移动端的表单、授权返回与目标选择均可独立完成。动效不延迟主操作。

## 5. 待确认与验收

当前需要确认的首要取舍：**欢迎页是否以外部 AI 接入为主入口，同时提供手动创建目标的短路径？** 推荐是，理由是匹配本轮已确认的核心使用场景。

其他设计建议与正式产品方案一起评审，不视为已批准实现。

验收场景包括：

- 已有任务的用户首次打开就能看到当前工作，未重复创建计划。
- 手动路径只填标题即可进入可开始状态。
- 地址已复制但无写入数据时，不展示虚假的计划成功。
- AI 写入只有目标／多目标／已有选择三种情况都有明确去向。
- 返回外部 AI 后能继续原路径；草稿、错误和重试状态可恢复。
- 开始前没有强制目标理由、偏好问卷或必看教学流程。
- 账户、时区、数据就绪状态正确；第一次计时是服务端真实记录。
