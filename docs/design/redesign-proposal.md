# AimThread 产品 redesign 方案

日期：2026-10-13

状态：行为基线来自已完成的访谈回答；布局、视觉、图表选择和实施分批为设计提案，等待评审。两套方向均满足同一产品契约。

## 1. 产品定位与核心流程

AimThread 是承接外部 AI 计划的执行与跟踪工具。用户在 AI 中把任务拆小，通过 MCP 写入目标、任务、说明与资源；回到 AimThread 后选择当前工作、计时并跟踪实际执行。

```text
外部 AI 制定计划并拆小任务
          ↓ MCP 写入
首页：选定目标和当前任务
          ↓ 用户点击开始
专注：任务内容 + 计时器 + 过程记录
          ↓ 每轮投入形成记录
到时等待 → 主动短休息／下一轮
          ↓ 整次执行结束
沿用结束反馈，可选完成任务、留下接续提示
          ↓
足迹：按日／周／月／年分析真实投入与完成情况
```

任务完成由用户明确操作。计时结束本身只证明发生了投入，不证明任务或目标完成。

## 2. 信息架构

| 区域 | 用户要完成的事 | 主要内容 |
| --- | --- | --- |
| 首页／今天 | 选好工作并开始 | 当前目标、当前任务、说明、资源、接续提示、计时模式、开始 |
| 首页目标选择弹窗 | 更换目标并找到工作 | 活跃目标、当前选择、对应任务、目标详情入口 |
| 专注状态 | 持续执行当前任务 | 工作内容、可见计时器、阶段、暂停／继续／结束、记录入口 |
| 足迹 | 理解投入与完成情况 | 周期选择、统计、趋势、目标分布、日历、独立执行记录 |
| 目标详情／管理 | 调整计划 | 目标与任务编辑、排序、完成、跳过、归档、重新打开 |
| 设置／连接 | 配置计时并维护外部 AI 连接 | 时间偏好、短休息、声音、时区、MCP 连接帮助 |
| 首次使用 | 建立可执行上下文 | 手动建立目标或连接外部 AI，找到已写入计划 |

主导航采用用户确认的左侧侧边栏，替代顶部 Tab。两个设计方向共用这一导航结构：上方是品牌与「今天／足迹」，底部放设置入口。目标选择始终直接从首页可达，目标管理不只藏在设置中。弹窗的具体结构在两个设计方向中分别处理。

### 2.1 侧边栏与内容区

- 桌面准备状态与足迹页面：左侧侧边栏展示图标和名称，右侧为主内容区；当前页面有清楚的选中状态。
- 专注状态：建议侧边栏收为图标列，减少导航的视觉权重。离开限制保持不变，折叠不表示可以跨页面继续计时。
- 移动端：建议用菜单按钮打开同一组导航的抽屉，保留页面标题，不把侧边栏硬挤进窄屏。菜单按钮不承担主操作。
- 目标选择继续由首页当前目标打开弹窗，不在侧边栏平铺所有目标与任务。
- 「今日时间线」是主内容区的辅助面板，与全局左侧导航职责分开。
- 足迹中的日／周／月／年是周期选择控件，留在足迹内容区；它们不属于本次被替换的顶部主导航。

左侧导航已经确认。专注时的折叠方式、移动端抽屉和侧边栏具体尺寸仍是待验证的布局建议。

## 3. 首页的共同契约

采用用户选定的 B 方向：突出当前工作，其他任务按需展开。下文的新方向一、方向二都属于这一结构，避免与此前 A／B 标签混淆。

- 首屏同时看见目标归属、当前任务、工作说明和开始按钮。
- 尚未开始时，用紧凑控件显示「番茄 · 25 分钟」或「正计时」；大号计时器在开始后出现。这是布局建议，不改变两种计时能力。
- 目标名称是明确的弹窗入口，不依赖用户发现图标才能操作。
- 任务说明和资源来自用户或 AI 写入；缺失时自然省略，不生成补写表单。
- 接续提示只对应当前任务；仅围绕目标执行时，只显示该目标的目标级提示。
- 「换个任务」按需展示当前目标下的待办。任务很多时支持查找与有限加载。
- 保留目标级执行能力：未选择任务也能开始，可选填写本次执行意图。
- 新任务追加或 AI 调整计划后，一个仍有效的显式选择保持稳定。
- 写入计划不自动启动计时；用户主动点击开始。
- 准备状态提供「今日时间线」入口，按需展开当天的实际投入。开始专注后默认收起；完整日期浏览与统计仍放在足迹。时间线的位置和展开方式为待评审建议，见 §8.1。

## 4. 专注、轮次与结束

### 4.1 专注页面

内容顺序为：目标归属 → 任务标题 → 工作说明与资源 → 清楚可见的计时器 → 当前阶段与控制 → 过程记录。

工作标题优先，计时器有足够字号和对比度。较长说明可以展开；资源用名称和链接呈现，单独打开。过程笔记与打断记录按现有能力保留。

开始后收起目标／任务切换入口和统计。计时期间的站内离开限制沿用现有行为：留在原页继续计时，或明确结束并保存后离开。保存失败留在原上下文并提供重试。刷新恢复计时不应丢失任务说明、资源和接续上下文。

### 4.2 每轮记录

用户确认四轮对应四条可见记录，不能只显示一条汇总记录并要求展开才能看到四轮。

每条记录至少展示：发生时间、目标、可选任务、实际专注时长。暂停、休息与等待不计入专注。提前结束的一轮记录实际投入，不凑整为 25 分钟。

领域上区分：

- **Focus Round（专注轮）**：番茄中的一个专注阶段。
- **Focus Interval（专注区间）**：真正发生投入的一段连续时间；一次暂停会把一轮拆成多个区间。
- **Session（执行过程）**：现有模型允许多轮与休息属于同一过程。

独立展示每轮记录已经确认；是否把每轮改成独立 Session 尚未确认。实现前需要确定映射，不能仅为了列表有四行就悄悄重写领域身份或重复统计。

统计主指标使用投入时间与完成任务数。若呈现“次数”，必须明确标注为专注轮数或执行次数，待记录映射确认后统一 Web 与 MCP 口径。

### 4.3 休息与结束

- 移除长休息。
- 到时不自动开始短休息；用户主动选择休息或开始下一轮。
- 不自动开始下一轮专注。
- 不要求用户为了记下已经发生的每轮投入额外点击结束。
- 结束反馈、任务完成操作和接续提示沿用现有方式；不新增逐轮 Toast、强制复盘或提示弹窗。
- 正计时由用户主动结束，按实际投入记录。

四轮等轮数组合结束整次执行的方式仍需要最终确认。用户否定强制手动结束；本提案保留自动收尾方向，避免把“每轮独立记录”直接等同于“一轮到时就关闭整个流程”。

## 5. 方向一：单页工作台

### 5.1 核心交互

同一块工作区域在准备、计时、到时等待之间变化。任务位置稳定，时间和操作在开始后出现。用户通过同一页面完成选择与执行。

```text
AimThread  │ 当前目标 ▾                         换个任务
           │ ──────────────────────────────────────────
今天       │ 发一篇文章
足迹       │ 完成开头两个案例，使用已整理的素材。
           │ 资源  文档链接 · 素材链接
           │ 接续提示（有内容时显示）
           │
           │ 番茄 25 分钟 ▾                 [开始专注]
           │ ──────────────────────────────────────────
设置       │ 今日投入摘要             今日时间线 ↗
```

开始后，任务内容保持位置，模式选择和摘要让位于时间、阶段与控制。主工作区保持单列，也不把每段内容都装成独立大卡片；左侧侧边栏承担全局导航。

### 5.2 目标与任务选择

首页打开一个组合选择弹窗：先列目标，选中目标后展示该目标的任务。当前工作有明确选中状态，点击任务完成选择并回到首页；目标级执行有独立选项。目标详情与新增入口位于弹窗次级区域。

弹窗是选择工具；大规模编辑进入目标详情，避免在选择过程中展开复杂管理表单。

### 5.3 足迹

采用分析工作台布局。顶部固定周期选择和日期范围，其下为实际投入、完成任务等摘要，再展示趋势与目标分布。点击时间柱、目标或日期，下方记录列表同步过滤。

### 5.4 视觉提案

浅灰白底、墨色文字、单一钴蓝操作色。使用细分隔线、清晰的文字层级和稳定的网格；少量容器用于选择与输入。时间使用等宽数字，与任务标题形成明确层级。

整体气质偏清晰、直接的工作工具，不沿用现有暖白橙色或深绿目标横幅。

### 5.5 取舍

优势是状态连续、操作位置稳定、桌面与移动端结构接近。风险是准备与专注的变化可能不够明显，需要通过收起次要信息、突出运行状态来表达已开始。

## 6. 方向二：任务页与专注场景

### 6.1 核心交互

首页像一张当前工作的任务页，使用与方向一相同的左侧导航。点击开始后进入同一路由中的专注场景，工作标题、必要说明、资源和计时器重新组织；侧边栏建议收为图标列，任务选择与分析入口退出主视线。

```text
首页：当前工作
目标选择 ▾

发一篇文章
任务说明 / 资源 / 接续提示

[开始专注]                       更换任务

                 ↓ 开始

专注场景
目标归属
发一篇文章
任务说明 / 资源

             24:38
          专注 · 第 1 轮
          暂停     结束

过程记录
```

这是同一产品执行状态的切换，不要求新增独立 focus 路由或复制一套计时状态机。

### 6.2 目标与任务选择

目标选择使用独立弹窗；选定目标后回到首页当前工作。任务从「更换任务」的独立选择面板进入。用户每次只处理一种选择，移动端可以使用全屏选择层。

### 6.3 足迹

采用周期报告布局：固定选择日／周／月／年，每个周期呈现适合该跨度的摘要与趋势。下钻打开当前周期的记录区域，保留周期和筛选上下文。

### 6.4 视觉提案

准备与统计使用高对比的浅色界面、石墨文字与少量青绿色强调。专注场景采用独立的深石墨背景，标题与时间保持高可读性。任务说明和链接不靠低对比度隐藏。

场景切换提供更明确的开始感；减少动态效果时直接切换。深色专注场景是待验证的视觉建议，不是新增的已确认主题偏好。

### 6.5 取舍

优势是准备与专注界限明确，执行时界面容易收敛。风险是场景变化可能让用户找不到任务说明或记录入口，需要保证信息可达、刷新后状态一致。

## 7. 两个方向的比较与建议

| 维度 | 方向一：单页工作台 | 方向二：任务页与专注场景 |
| --- | --- | --- |
| 进入专注 | 原位出现计时与控制，次要信息收起 | 进入独立的专注场景 |
| 信息位置 | 任务内容位置稳定 | 按执行状态重新组织 |
| 选择工作 | 组合目标／任务弹窗 | 分别选择目标和任务 |
| 足迹结构 | 同一分析工作台中联动下钻 | 按周期组织报告再下钻 |
| 视觉 | 浅色、钴蓝、细分隔、低容器密度 | 浅色准备与统计、深色专注场景 |
| 更适合 | 经常查看说明与资源、重视连续操作 | 希望点击开始后有明显场景转换 |

**设计建议：先验证方向一。** 它围绕现成任务直接开始，切换成本较低，移动端也能沿用同一结构。方向二作为对照，验证明显的专注场景是否更有帮助。用户尚未选择本轮的新视觉方向。

## 8. 日／周／月／年分析

周期切换改变日期范围与图表粒度，指标口径保持一致。下面的图表和交互为设计建议。

| 周期 | 范围与浏览 | 趋势呈现 | 下钻 |
| --- | --- | --- | --- |
| 日 | 某一天；前一天／后一天／今天 | 真实专注区间的时间分布 | 当天每轮记录与任务 |
| 周 | 某一自然周；沿用用户周起始日 | 每日投入柱状图 | 某一天、某目标 |
| 月 | 某一自然月；前月／后月／本月 | 每日投入趋势与活动日历 | 某一天、某目标 |
| 年 | 某一自然年；前年／后年／今年 | 按月汇总投入趋势 | 某个月及其记录 |

### 8.1 执行时间线（新增提案）

用户补充了一张带小时刻度、执行色块与当前时间线的参考图，并明确表示喜欢时间线功能。已确认的是对该能力的兴趣；以下位置、交互和范围是设计建议，尚未确认。

**主入口：足迹的日视图。** 顶部保留当天统计与日期切换，下方展示按真实时钟排列的执行时间线。每个专注轮独立可辨，色块标注任务、起止时间和实际投入；点击查看任务归属、记录与笔记。按目标使用稳定颜色，并同时提供文字标签。

**辅助入口：首页准备状态的「今日时间线」。** 默认收起。桌面按需打开侧面板，移动端打开抽屉；开始专注时收起，保持当前工作与计时器的视觉优先级。首页只回看今天，完整日期浏览进入足迹，不永久占据第二栏。

```text
足迹 · 日
[日 / 周 / 月 / 年]          ‹ 10 月 13 日 ›

当天实际投入     完成任务     目标分布
──────────────────────────────────────
09:00   [ 写文章 · 25 分钟 ]
        等待或休息留白
10:00   [ 写文章 · 25 分钟 ]
11:00   [ 整理素材 · 18 分钟 ]
──────────────────────────────────────
记录详情与补录入口
```

周视图继续使用每日投入趋势，点击一天进入对应时间线；月、年视图逐级下钻到日。周七列时间网格暂列后续可选方案，避免这轮同时扩展成日程管理。

时间线提案以已经发生的执行为基础：

- 专注到时、暂停与休息均按真实边界显示。暂停间隔留白，同一轮的多个专注区间使用关联标记，不能把整个墙钟跨度涂成有效专注。
- 今天可以显示当前时刻标线；未来区域不填充为已发生投入。
- 正在计时的记录延伸到当前服务端观测时刻，足迹仍只通过用户允许的导航流程进入。
- 补录／纠错有明确标识；仅知道汇总时长时，不伪造精确的专注位置。
- 日统计与色块累计使用相同口径，跨日轮次在两天按实际区间展示，保留同一轮的身份。
- 资源原链接与时间线记录详情均不改变当前计时对象。

未来计划的拖拽排程、预约时间块、日历集成尚未确认，不由这张参考图自动加入范围。

共同摘要：当前周期实际投入、完成任务数、各目标投入分布。累计投入可以作为独立的全量摘要，不能混充当前周期数据。

“分析”在本提案中指趋势、分布和下钻；同比、环比、预测、自动解释与 AI 建议未获确认，不按必做范围承诺。

规则：

- 所有摘要、图表、列表使用相同周期、时区和目标筛选。
- 真实投入排除暂停、休息、到时等待；取消记录按既有规则排除。
- 跨日专注按实际区间与本地日期的交集分配，跨月、跨年同理。
- 一轮有多段 Focus Interval 时，汇总成一条轮记录；不能把暂停恢复误算成多轮。
- 多轮与 Session 的总量不能重复相加。
- 完成任务数沿用显式完成的口径，不由番茄轮数推算。
- 补录与纠错明确标识，不能伪造具体专注发生位置。
- 未来时间不显示为已发生的零投入；空周期提供中性空状态。

## 9. 管理、首次使用与连接

### 9.1 目标和任务管理

首页选择弹窗负责切换；目标详情负责调整。任务编辑能看到标题、说明、资源与状态；排序、归档等放在次级操作。计时中的工作对象保持固定，状态冲突给出返回当前执行的入口。

### 9.2 首次使用与 MCP

用户已提出首次打开体验需要优化。详细的状态分流、首屏、MCP 写入衔接与手动短路径见 [首次打开与 Onboarding 提案](onboarding.md)。

有已写入目标时直接展示可执行任务。没有目标时建议用简洁欢迎页提供两个明确入口：连接外部 AI、手动建立目标。连接帮助与计划是否写入分开反馈；不能把“点击连接”当作“已有计划”。

用户在外部 AI 中确认计划后写入。产品内不增加聊天或再次拆解任务的前置步骤。保留完全手动使用路径。

## 10. 验证与实施顺序建议

1. 评审当前文档，确认记录映射与一个界面方向。
2. 用同一组样例数据制作两个方向的可交互预览，覆盖首页、选择弹窗、专注、到时等待、足迹周期切换和移动端。
3. 同步 PRD 与领域契约；整体拆分实现，不以保留旧布局作为前提。
4. 接入真实 MCP 写入、服务端计时、每轮记录与跨周期统计，验证完整链路。
