# Google / GitHub 登录与独立个人账户

## Problem Statement

AimThread 目前采用单实例单用户体系：第一次访问创建固定 owner，之后使用实例密码登录。其他人无法通过自己的 Google 或 GitHub 身份注册并独立使用同一个网站。

限制不仅存在于登录入口。当前业务数据没有用户归属，设置和当前选择为全站单例，整个实例只能存在一个未结束的 Session，业务服务与 MCP 入口没有传递真实用户身份。直接开放社交登录会使用户共享目标、执行记录、偏好和 AI 可访问的数据，无法满足个人账户的基本预期。

产品尚未上线，既有数据无需保留。此次应完整建立多用户隔离，避免引入旧 owner 迁移与兼容负担。

## Solution

任何人都可以在同一个 AimThread 网站通过 Google 或 GitHub 登录；首次成功登录自动建立个人账户，后续登录回到自己的工作现场。切换后只保留这两种登录方式，移除实例密码、固定 owner 和首次设置密码流程。

每个 User 独立拥有 Goal、Task、Session、偏好、当前选择、引导状态、Footprint 和 AI 授权。不同用户可以同时执行；同一用户在不同设备与 Web/MCP 之间继续同一份工作。

Google 与 GitHub 邮箱相同，且已有用户邮箱与新登录身份邮箱均已验证时，自动关联至同一 User。不同邮箱对应独立 User，本轮不提供主动绑定、解绑或独立用户之间的数据合并。

AI 连接保持可选。从 ChatGPT 发起连接的未登录用户先完成 Google/GitHub 登录，随后自动返回原授权页；明确同意后，ChatGPT 只能访问该用户的数据。普通网页登录后可直接使用产品。

## User Stories

1. 作为首次访问者，我希望使用 Google 登录并自动建立个人账户，以便直接开始使用 AimThread。
2. 作为首次访问者，我希望使用 GitHub 登录并自动建立个人账户，以便沿用已有开发者身份。
3. 作为首次访问者，我希望无需邀请码或管理员批准即可注册，以便自主开始使用产品。
4. 作为用户，我希望登录页面清楚提供 Google 与 GitHub 两个入口，以便选择自己常用的方式。
5. 作为用户，我希望登录过程不再要求设置或输入实例密码，以便理解这是自己的个人账户。
6. 作为返回用户，我希望使用之前的登录身份回到同一账户，以便继续已有工作。
7. 作为同时使用 Google 与 GitHub 的用户，我希望相同且双方均已验证的邮箱进入同一账户，以便更换登录入口后仍能看到原有数据。
8. 作为用户，我希望未验证邮箱不会触发自动账户关联，以便保护现有账户。
9. 作为使用不同邮箱的用户，我希望两个登录身份对应独立账户，以便避免意外混合不同的数据。
10. 作为用户，我希望登录取消、提供商拒绝或网络失败时看到可恢复的提示，以便重试或改用另一个登录入口。
11. 作为用户，我希望重复点击登录入口或重试回调不会建立重复账户，以便账户身份保持稳定。
12. 作为首次登录用户，我希望获得独立的设置和引导状态，以便按自己的情况开始使用。
13. 作为用户，我希望自行设置名称、时区和计时偏好，以便产品符合自己的使用习惯。
14. 作为用户，我希望创建的 Goal 只属于自己，以便维护私人的执行计划。
15. 作为用户，我希望 Task、资源和备注跟随自己的 Goal 隔离，以便他人无法访问我的具体工作内容。
16. 作为用户，我希望 Session、Focus Interval、Distraction 与 Resume Hint 只属于自己，以便保护执行现场和记录。
17. 作为用户，我希望首页、列表、详情、搜索、分页和执行上下文只包含自己的数据，以便不会看见其他用户的内容。
18. 作为用户，我希望当前选择和接续提示独立保存，以便别人切换工作时不会改变我的执行现场。
19. 作为用户，我希望自己的 Footprint、统计、投入汇总和活动日历只计算自己的记录，以便看到准确的个人投入。
20. 作为用户，我希望与其他用户同时运行 Session，以便各自独立使用产品。
21. 作为用户，我希望同一账户最多存在一个未结束的 Session，以便多设备和 AI 操作保持一致。
22. 作为用户，我希望在另一设备登录后能恢复自己的未结束 Session，以便继续之前的执行。
23. 作为用户，我希望暂停、恢复、阶段切换、结束和取消都只影响自己的 Session，以便不干扰其他人。
24. 作为用户，我希望补录、纠错和时间重叠检查限定于自己的记录，以便他人的时间安排不阻塞我。
25. 作为用户，我希望重试创建或计时请求时只复用自己的幂等结果，以便不会读取或修改其他用户的数据。
26. 作为用户，我希望即使他人知道我的对象 ID 也无法查看或修改数据，以便数据隐私不依赖 ID 难以猜测。
27. 作为用户，我希望失效链接和越权请求得到明确且不泄露他人内容的结果，以便安全地恢复操作。
28. 作为用户，我希望退出登录后本浏览器不能继续访问受保护页面，以便结束当前登录状态。
29. 作为在共用浏览器切换账户的用户，我希望旧账户的草稿、选择和缓存不会出现在新账户，以便避免数据串用。
30. 作为只使用 Web 的用户，我希望无需连接 AI 即可完成目标创建和执行，以便独立使用全部核心流程。
31. 作为从 ChatGPT 发起连接的用户，我希望先完成 Google/GitHub 登录再自动回到原授权页，以便不中断连接流程。
32. 作为用户，我希望确认授权后 ChatGPT 只能访问我的数据，以便安全地通过 AI 管理目标与执行。
33. 作为用户，我希望拒绝或取消 AI 授权时不会授予访问权限，以便保留对连接的控制。
34. 作为用户，我希望自己的 Web 操作和 MCP 操作看到相同的数据与状态，以便在两个入口之间接续工作。
35. 作为用户，我希望另一个用户的 MCP 授权或调用无法读取或修改我的对象，以便 AI 入口遵守相同的隐私边界。
36. 作为用户，我希望管理自己的 AI 授权时不会影响其他用户，以便每个人独立控制连接。
37. 作为用户，我希望第三方登录后只回到合法的站内目的地，以便避免被恶意回跳地址带到其他网站。
38. 作为用户，我希望 Google/GitHub 提供的名称能够正常用于首次建号，并继续允许编辑个人名称，以便顺利完成登录和个人设置。
39. 作为开发者，我希望本地环境能完成真实 Google/GitHub 登录，以便验证完整第三方回调。
40. 作为产品维护者，我希望正式域名能完成真实登录和 ChatGPT 授权，以便上线前验证用户实际使用的流程。
41. 作为产品维护者，我希望获得准确的环境变量与回调地址清单，以便正确配置两家 OAuth 提供商。
42. 作为产品维护者，我希望能从空数据库建立完整的多用户系统，以便无需保留尚未上线的测试数据。

## Implementation Decisions

- 保留现有 Better Auth、PostgreSQL/Drizzle、Web 与 MCP 共用领域服务的架构。参考 Transcriptly Web 的社交登录、已验证邮箱关联、令牌保护与安全回跳实践，按 AimThread 当前依赖版本核对接口，不复制其公开字幕档案或扩展专属逻辑。
- 登录页面与认证后端同时切换为 Google/GitHub；关闭邮箱密码注册和登录，删除固定 owner 限制与首次实例密码初始化语义。不能只隐藏旧入口而留下可调用的密码接口。
- User 是稳定的数据所有者，Login Identity 是 Google 或 GitHub 的登录身份。提供商稳定账户标识用于识别已有关联；邮箱仅用于符合已确认条件的自动关联，不作为客户端可自行声明的所有权依据。
- 自动关联要求相同邮箱、已有用户邮箱已验证、新登录身份邮箱已验证；不将提供商无条件标记为可信来绕过验证要求。条件不足时拒绝自动关联，不泄露既有账户内容；不以合并业务数据的方式补救。
- 首次登录建号和重复回调必须遵守提供商身份唯一性及邮箱唯一性约束；并发请求不能产生重复 User 或将同一 Login Identity 归给不同 User。
- 社交令牌按框架能力加密保存；完成身份验证后不保留业务不需要的 ID token。凭证与令牌不得出现在源码、日志、错误提示或浏览器可见配置中。
- 保留现有名称编辑能力，对提供商名称采用符合产品规则的初始化处理，避免直接套用人工输入校验导致合法社交登录无法建号。
- Web 登录读取返回已验证的真实用户身份，代替仅有登录布尔值的上下文。业务认证上下文同时携带 userId 与入口来源；每个受保护页面、Server Action、Route Handler 和服务操作均传播该身份。
- MCP 从已校验的 access token 获取授权主体，并在每次请求中传入领域服务；保留 issuer、audience/resource、有效期和 scope 校验。缺失或无效主体不能回退到默认用户，也不能只凭 scope 访问业务数据。
- 浏览器或工具调用传入的 userId 不作为权限依据。拒绝跨用户的读取、编辑、排序、状态切换、选择、计时、补录、纠错和上下文获取；按现有错误契约返回未找到或无权限，不回显他人数据。
- Goal、Session、用户设置和幂等记录具备明确用户归属；Task、Focus Interval、阶段、Distraction 等下级对象必须沿已验证的所属关系隔离。数据库约束与服务端所有权检查共同防止跨用户拼接 Goal、Task 与 Session。
- 修改列表、详情、分页、搜索、首页、Footprint、统计和执行报告查询，所有结果及聚合按用户限定；更新或删除类操作也必须携带同样的所有权条件。
- 将全站设置单例改为每用户设置，独立保存时区、计时偏好、当前选择、引导完成状态等；默认值不能从另一个 User 的设置中继承。
- 未结束 Session 的唯一性由全站一条改为每用户一条，专注、休息、暂停、到时等待都占用该用户的位置；不同用户可并发执行。同一用户多端请求仍遵守现有事务与状态机规则。
- 幂等键按用户与操作限定作用域；相同用户、相同操作和 key 的既有重试语义保持不变，不同用户使用相同 key 不共享结果。业务锁、时间重叠检查、排序位置和选择推进也应限定于相应用户及对象作用域。
- 维护现有计时写入通路及持久化语义，避免以多用户改造为由重新引入无关的阻塞路径或改变已保存时间的含义。
- 浏览器持久化草稿和缓存按站点与用户隔离，退出或切换身份时清理旧账户状态；服务端缓存如存在，同样必须包含用户作用域。
- 保留现有站内安全回跳规则。普通登录完成后按该用户的 setup/onboarding 状态继续；从 ChatGPT 发起的登录保留受保护的原授权上下文并返回原授权页，不能在社交回调后丢失该上下文或被首次引导替换。
- 社交登录不会代替 MCP 授权同意。用户只有完成原授权流程才为 ChatGPT 授权；已有登录时可直接进入原同意流程。AI 连接仍可跳过，授权的读取、管理及撤销按用户隔离。
- 正式站点使用 `https://aimthread.com`，本地开发使用 `http://localhost:3000`。本轮配置与真实验收覆盖两者，不要求每个 Vercel Preview 地址支持真实登录；需要远程测试时后续配置固定测试域名。
- 沿用现有会话期限与 Cookie 保护、同源写入保护和速率限制；本轮不新增通用权限角色系统。无凭证或配置错误必须给出可诊断结果，不能回退为共享测试用户或实例密码。
- 不保留旧 owner 与测试业务数据，不实现回填、双写或兼容 adapter。提交可复现的建库/schema 初始化方案与测试数据初始化调整；本规格的发布不执行数据库清理。
- 同步产品文案、部署指南、环境变量示例、领域文档和受影响测试，消除单实例单用户及实例密码表述；功能上线状态以真实实施与验收证据为准。

## Testing Decisions

- 用户已确认测试边界：以两个独立 User 从真实 Web/MCP 入口操作的外部可观察行为作为主要验收边界，复用现有 Playwright、真实应用服务与隔离数据库。优先在这一边界验证完整流程，不为每个查询函数增加新的测试接口，不以 mock 服务证明数据隔离。
- 良好测试应证明“用户能做什么、不能做什么，以及另一用户的数据是否保持原样”，不绑定私有函数调用顺序或复制实现细节。对确有必要的唯一性、外键和并发约束，在现有数据库集成边界补充测试。
- 现有先例包括：首次使用到退出登录的浏览器流程、OAuth discovery 与 scoped MCP 调用、Web/MCP 执行上下文一致性、真实数据库初始化/外键/并发测试、回跳校验与签名授权参数校验，以及计时 Route Handler 的未登录和跨域拒绝测试。复用这些测试体系并移除对固定 owner 和实例密码的依赖。
- 自动化用相互独立的浏览器上下文及具有真实 User 归属的 Web 登录会话/MCP token；第三方网络可采用受控测试替身，但应用自身的鉴权、所有权检查、领域服务与数据库必须走真实路径。不增加生产可用的绕过登录入口，不能仅注入 userId 或伪造已登录布尔值来完成验收。
- 登录与关联矩阵覆盖：Google 首登、GitHub 首登、同提供商返回登录、双方同邮箱且均已验证的关联、任一邮箱未验证时不自动关联、不同邮箱独立建号、重复/并发回调、取消/失败后恢复，以及后台密码注册和登录确实不可用。
- 两用户隔离矩阵覆盖 Goal/Task/Session 的列表、详情、写入与排序，资源、备注、Resume Hint、Distraction，设置、当前选择和引导，Footprint、统计和复制给 AI 的执行上下文。A 访问 B 的已知 ID、拼接跨用户父子对象或伪造所有者均失败；失败后 B 的数据保持原样。
- 并发验收包括 A/B 各自同时拥有一个未结束 Session、同一 User 两次并发开始最多成功一次、不同用户的时间重叠互不阻塞、同一幂等 key 在两用户间独立且同一用户重试不重复落账。验证状态隔离，不编写依赖脆弱墙钟阈值的锁性能测试。
- 同一 User 的 Web 和 MCP 交替创建、选择、开始、暂停、结束后观察到一致状态；A 的 MCP token 不能触达 B 的对象。错误主体、缺失主体、无效令牌、错误 audience/resource 以及 scope 不足继续被拒绝；管理一个用户的授权不影响另一个用户。
- 浏览器回归覆盖首次设置、引导、直接使用 Web、返回原受保护页面、站外回跳拒绝、刷新恢复、退出后页面保护，以及同一浏览器退出 A 再登录 B 后不显示 A 的缓存或草稿。保留现有计时与离开确认的相关回归。
- 验证从空隔离数据库运行提交的初始化/schema 变更成功且可重复执行；绝不把现有开发或正式数据库当作可清理测试库。
- 本地和正式环境分别完成真实 Google 与 GitHub 浏览器登录，并验证从 ChatGPT 发起连接、社交登录、返回原授权页、明确同意和实际读写自己数据的完整链路。自动化使用测试 token 的成功不能代替真实提供商回调或真实 ChatGPT 授权的证据。
- 运行与变更相符的类型、代码质量、单元、数据库集成及端到端检查；交付时分别记录自动化结果、提供商真实登录结果、部署结果及真实 AI 客户端结果。缺少凭证或人工客户端验证时明确标记尚未验证，不能报为全链路完成。

## Out of Scope

- 团队、组织、共享 Goal、工作空间、多角色权限或用户间协作与社交。
- 邮箱密码注册/登录、实例密码、邮件验证或找回密码服务、自定义身份提供商。
- 不同邮箱主动绑定、登录身份解绑、已有独立 User 的数据合并或账户转移。
- 旧 owner 认领、旧测试数据保留、历史数据回填、双写和兼容层。
- 每个 Vercel Preview 域名的真实登录支持、统一 OAuth 回调代理或新增部署平台。
- 订阅付费、通用后台管理、账户删除/数据导出产品流程。
- 新增 Claude 或其他 AI 客户端支持、Plugin/Skill 分发、通用身份平台；已有 AI 接入增强事项仍由其原有 Issue 承载。
- 核心执行模型、计时语义或信息架构的额外重设计。

## Further Notes

- 2026-10-18 已确认全部产品决策、正式/本地环境范围及测试边界；依据 ADR-0001 与 ADR-0002。多用户与第三方登录是本轮主动变更，替代此前 PRD 对单实例单用户的限定。
- 当前仅形成规格与领域文档，尚未实现功能、清理数据库、配置 OAuth 提供商或部署变更。
- 参考来源为 Transcriptly 的 Web 实现；该参考是代码层面的实现先例，不代表本轮 AimThread 的真实登录已经验证。
- OAuth 凭证由用户提供或配置；实现所需环境变量为 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`，沿用 `DATABASE_URL`、`BETTER_AUTH_SECRET`、`BETTER_AUTH_URL`。密钥不写入 Issue、提交或文档。
